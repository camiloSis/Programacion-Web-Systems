🎯 Objetivos de aprendizaje

Al terminar, el estudiante será capaz de:

  1. Describir los diferentes algoritmos de ordenamiento y los paradigmas usados para su diseño (p. ej. divide et impera para merge sort y quicksort).
  2. Demostrar la corrección (o incorrección) de cada algoritmo.
  3. Implementar cada algoritmo correctamente.
  4. Analizar y comparar por: estabilidad, eficiencia en tiempo y memoria, número de comparaciones, de intercambios…
  5. Seleccionar el algoritmo adecuado al tipo de dato.

🧭 Qué veremos y qué hay que saber

Algoritmos: 1) Insertion sort · 2) Selection sort · 3) Heap sort · 4) Merge sort · 5) Quicksort · y la cota inferior (lower bound).

Se debe aprender a: describir cada algoritmo; compararlos en eficiencia de tiempo/memoria y otras características; usarlos según las necesidades.

Conocimiento previo: análisis de algoritmos, notación asintótica, estructuras de datos (árboles, heaps).

❓ ¿Qué es ordenar (sorting)?

Es el proceso de reorganizar elementos en un cierto orden. Se pueden ordenar números, palabras, cadenas, objetos…

  • Dónde se usa: bases de datos (registros de estudiantes por nombre o nota), Google (resultados por relevancia), Amazon (por precio)…
  • Por qué importa: muchos algoritmos lo requieren como parte fundamental: búsqueda binaria, Kruskal (MST), Graham (envolvente convexa / convex hull)…

Ordenamiento por comparación

Ordena comparando elementos. Ej.: ordenar de forma no decreciente {2♠, 3♥, 3♣, 4♥, 5♠, 6♥, 7♣, 7♦, 9♠}

⭐ Es el tema de esta clase.

Ordenamiento por distribución

Ordena distribuyendo elementos (sin compararlos entre sí). Ej.: repartir cartas por palo {A♠, K♠, Q♥, J♥, K♣, Q♣, Q♦, K♦}

1 Características de los algoritmos de ordenamiento

Cuatro «etiquetas» para comparar cualquier algoritmo. Se usarán durante todo el resumen.

⚡ Eficiente

Ordena n elementos en O(n log n).

Se debe a la cota inferior de Ω(n log n) comparaciones (sección 7).

🔄 Adaptativo

Aprovecha el orden existente en la entrada.

Ordena más rápido una entrada casi ordenada.

📦 In-place

Requiere a lo sumo O(log n) de espacio adicional.

Además del O(n) que ya ocupa la entrada.

⚖️ Estable

Mantiene el orden relativo de elementos con claves iguales.

Si 5♥ aparece antes que 5♠ en la entrada, debe seguir antes en la salida.

Ejemplo de estabilidad

Entrada: {5♥, 3♣, 8♣, 2♦, 5♠}

  • Salida estable: {2♦, 3♣, 5♥, 5♠, 8♣} (5♥ sigue antes que 5♠)
  • Salida no estable: {2♦, 3♣, 5♠, 5♥, 8♣} (los dos 5 se invirtieron)

2 Insertion sort (ordenamiento por inserción)

💡 Analogía: es como ordenar las cartas que tienes en la mano: tomas una carta nueva y la colocas en su lugar entre las que ya están ordenadas.

Algoritmo

Entrada: lista desordenada I · Salida: lista ordenada S

1: S ← lista vacía
2: for each x in I do
3:     quitar x de I
4:     buscar la posición ordenada de x en S
5:     insertar x en S en esa posición
6: return S

Idea: insertar el siguiente elemento en S en una posición ordenada.

Invariante: S está ordenada y contiene los elementos que se han quitado de I.

Traza paso a paso

S (ordenada)I (pendiente)
∅{5♥, 3♣, 8♣, 2♦, 5♠}
{5♥}{3♣, 8♣, 2♦, 5♠}
{3♣, 5♥}{8♣, 2♦, 5♠}
{3♣, 5♥, 8♣}{2♦, 5♠}
{2♦, 3♣, 5♥, 8♣}{5♠}
{2♦, 3♣, 5♥, 5♠, 8♣}∅

Fíjate que 5♠ se inserta después de 5♥ → eso hace al algoritmo estable.

Peor caso: O(n²)

Las operaciones más caras son las líneas 4 y 5 (buscar e insertar).

  • Si S es un arreglo: O(n) para desplazar los elementos mayores.
  • Si S es una lista enlazada: O(n) para encontrar la posición.

Se repite para n elementos → O(n²).

Mejor caso: Ω(n)

  • Si la entrada ya está ordenada, se verifica en Ω(n).
  • Si está casi ordenada: complejidad Θ(n + i), donde i es el número de inversiones.

Inversión = par de elementos fuera de orden. Por eso es adaptativo.

Caso promedio: O(n²)

El número de inversiones está en i ∈ [0, n(n−1)/2].

Si una permutación tiene i inversiones, su reversa tiene n(n−1)/2 − i.

Promediando cada par de permutaciones:

(n(n−1)/2 − i + i) / 2 = n(n−1)/4 ∈ O(n²)

EficienteAdaptativoIn-placeEstable

🌳 Tree sort: ¿y si usamos otra estructura para S?

Pregunta de la lámina: ¿podemos usar otra estructura de datos para S con búsqueda e inserción más rápidas que arreglos y listas enlazadas?

  • En un árbol binario de búsqueda autobalanceado, buscar e insertar cuesta O(log n).
  • Tree sort = Insertion sort con S implementado como ese árbol.
  • Insertar todos los elementos: O(n log n); recorrer en orden para la salida: O(n).
  • NO es in-place. Es eficiente pero rara vez usado: el balanceo hace cada inserción muy costosa y la O oculta una constante alta.

3 Selection sort (ordenamiento por selección)

💡 Analogía: de la pila desordenada eliges siempre la carta más pequeña y la pones al final de tu fila ordenada.

Algoritmo

1: S ← lista vacía
2: for i = 1 to n do
3:     x ← elemento de I con la menor clave
4:     quitar x de I
5:     añadir x al final de S
6: return S

Invariante: S está ordenada y contiene los elementos más pequeños quitados de I.

Truco para quitar el mínimo rápido: intercambiarlo (swap) con el primer elemento de I. Esto lo hace NO estable.

In-place y NO estable.

Traza (con swap)

Entrada: {5♥, 8♣, 5♠, 2♦, 3♣}

SI
∅{5♥, 8♣, 5♠, 2♦, 3♣}
{2♦}{5♥, 8♣, 5♠, 3♣}
{2♦, 3♣}{5♠, 5♥, 8♣}
{2♦, 3♣, 5♠}{5♥, 8♣}
{2♦, 3♣, 5♠, 5♥}{8♣}
{2♦, 3♣, 5♠, 5♥, 8♣}∅

Los dos 5 terminan invertidos (5♠ antes que 5♥) → inestable.

🫧 Bubble sort (nota de la lámina)

Es un ordenamiento estable «tipo selección» que requiere desplazar los demás elementos para reubicar el menor, en lugar de hacer un swap.

Esos desplazamientos cuestan O(n) y duplican el costo de Selection sort.

Complejidad: siempre O(n²)

  • Línea 3: buscar el menor en un conjunto desordenado es O(n) (arreglo o lista).
  • Línea 4: un swap es O(1).
  • Total: O(n²) en peor, mejor y promedio, con arreglo o lista enlazada.
  • No es adaptativo: ordenar una entrada ya ordenada cuesta lo mismo.

Pista: el cuello de botella es encontrar la menor clave → reemplazar I por una cola de prioridad → Heap sort.

4 Heap sort (ordenamiento por montículo)

💡 Idea: primero «tiras» todos los elementos desordenados en un heap; luego sacas repetidamente el siguiente elemento ordenado (el máximo).

Algoritmo

1: H ← BottomUpMaxHeap(I)
2: S ← lista vacía
3: for i = 1 to n do
4:     x ← RemoveMax(H)
5:     añadir x a S
6: return S

Invariante: S está ordenada y contiene los elementos más grandes quitados de H.

Propuesto por Floyd (1962, 1964) y Williams (1964).

¿Qué es un heap binario?

Un árbol binario completo con la propiedad de max-heap: cada padre es ≥ que sus hijos.

        7
      /   \
     6     5
    / \   / \
   4   3 2   1

Se representa fácil como arreglo (raíz en posición 1):

  • Padre de i: ⌊i/2⌋
  • Hijos de i: 2i y 2i+1
  • Raíz: 1

[7, 6, 5, 4, 3, 2, 1]

Fase 1 · Construir el heap (BottomUpMaxHeap)

BottomUpMaxHeap(I):
1: «tirar» I en H
2: for i = ⌊n/2⌋ to 1 do
3:     SiftUp(H[i])
4: return H

Repara la propiedad max-heap desde los padres de abajo hasta la raíz usando SiftUp.

SiftUp(H[i]):
1: if H[i] tiene hijo then
2:     maxChild ← hijo máximo
3:     if H[i] < H[maxChild] then
4:         swap(H[i], H[maxChild])
5:         SiftUp(H[maxChild])

📝 Nota: en la lámina se llama «SiftUp», pero lo que hace es hundir el nodo intercambiándolo con su hijo mayor (en otros libros se llama sift-down / heapify).

Traza con H = {5♥, 8♣, 5♠, 2♦, 3♣, 9♦, 7♠}:

  1. Se empieza en el nodo 3 (5♠): su hijo mayor es 9♦ → swap → {5♥, 8♣, 9♦, 2♦, 3♣, 5♠, 7♠}
  2. Nodo 2 (8♣): ya es mayor que sus hijos 2♦ y 3♣ → no cambia.
  3. Nodo 1 (5♥): se intercambia con 9♦ y luego con 7♠ → {9♦, 8♣, 7♠, 2♦, 3♣, 5♠, 5♥} ✅ heap listo.

Fase 2 · Extraer el máximo (RemoveMax)

RemoveMax intercambia la raíz con el último elemento del heap, lo saca (va a S) y llama a SiftUp sobre la raíz para reparar el heap.

H (heap)S
{9♦, 8♣, 7♠, 2♦, 3♣, 5♠, 5♥}∅
{8♣, 5♥, 7♠, 2♦, 3♣, 5♠}{9♦}
{7♠, 5♥, 5♠, 2♦, 3♣}{8♣, 9♦}
{5♥, 3♣, 5♠, 2♦}{7♠, 8♣, 9♦}
{5♠, 3♣, 2♦}{5♥, 7♠, 8♣, 9♦}
{3♣, 2♦}{5♠, 5♥, 7♠, 8♣, 9♦}
{2♦}{3♣, 5♠, 5♥, 7♠, 8♣, 9♦}
∅{2♦, 3♣, 5♠, 5♥, 7♠, 8♣, 9♦}

Observa: en la entrada 5♥ iba antes que 5♠, y en la salida 5♠ va antes que 5♥ → no es estable.

5 Merge sort (ordenamiento por mezcla)

💡 Paradigma divide y vencerás: la partición es trivial (cortar por la mitad) y todo el trabajo ocurre al mezclar dos listas ya ordenadas.

Algoritmo (recursivo)

1: if I tiene un elemento then
2:     return S = I
3: else
4:     partir I en I₁ e I₂ con ⌈n/2⌉ y ⌊n/2⌋ elementos
5:     ordenar I₁ recursivamente → S₁
6:     ordenar I₂ recursivamente → S₂
7:     mezclar S₁ y S₂ en S
8: return S

Divide (partir) → Merge sort a cada mitad → Merge (mezclar).

Operación Merge

Entrada: dos listas ordenadas S₁ y S₂ · Salida: lista ordenada S

1: S ← lista vacía
2: loop
3:   if S₁.front() ≤ S₂.front() then
4:       mover S₁.front() a S
5:       if S₁ vacía then break
6:   else
7:       mover S₂.front() a S
8:       if S₂ vacía then break
9: concatenar los restantes al final de S
10: return S

Cuesta O(n). Es natural para listas enlazadas; con arreglos usa memoria adicional.

El «≤» (y no «<») hace que ante claves iguales salga primero la de S₁ → conserva la estabilidad.

Traza de la mezcla

S₁ = {3♣, 5♥, 8♣} y S₂ = {5♠, 7♠, 9♦} → se comparan los frentes:

3♣ vs 5♠ → 3♣ · 5♥ vs 5♠ → 5♥ · 8♣ vs 5♠ → 5♠ · 8♣ vs 7♠ → 7♠ · 8♣ vs 9♦ → 8♣ · sobra 9♦

Resultado: S = {3♣, 5♥, 5♠, 7♠, 8♣, 9♦}

Versión iterativa

Se corta la lista en n listas de tamaño 1 y luego se mezclan listas de tamaño 2i (1→2→4→8…) hasta quedar una.

Ej.: {5♥, 2♦, 8♣, 5♠, 3♣} → pares: {2♦,5♥}, {5♠,8♣}, {3♣} → {2♦,5♥,5♠,8♣}, {3♣} → {2♦, 3♣, 5♥, 5♠, 8♣}

Complejidad: O(n log n)

  • El árbol de subproblemas tiene 1 + ⌈log n⌉ niveles.
  • En cada nivel el costo total de mezclar es c·n (ej.: 2·cn/2, 4·cn/4, 8·cn/8…).
  • Total: (1 + ⌈log n⌉)·cn ∈ O(n log n) en peor, mejor y promedio.

Estable, pero NO in-place (espacio O(n)).

6 Quicksort

💡 Divide y vencerás, pero al revés que merge sort: la unión es trivial (concatenar) y el trabajo ocurre al particionar alrededor de un pivote.

Algoritmo general

1: elegir un pivote v de la lista I
2: partir I en I₁ e I₂ tales que:
     – I₁ contiene ítems con clave k ≤ v
     – I₂ contiene ítems con clave k ≥ v
     – los ítems con k = v pueden ir en cualquiera de las dos
3: ordenar I₁ recursivamente → S₁
4: ordenar I₂ recursivamente → S₂
5: concatenar S₁ y S₂ en S
6: return S

Pregunta de la lámina: ¿partición de Hoare o de Lomuto?

Partición de Lomuto [CLRS22]

1: pivot = A[low]
2: i = low + 1
3: for j = i to high do
4:     if A[j] ≤ pivot then
5:         swap(A[i], A[j])
6:         i = i + 1
7: swap(A[i−1], A[low])
8: return middle = i − 1

Invariantes: los ítems a la izquierda de i tienen clave ≤ pivot; los de i a j−1 tienen clave > pivot.

middle es la posición final del pivote. Caso promedio: n/2 swaps.

Traza (pivote 5♥) sobre {5♥, 2♦, 8♣, 3♣, 9♦, 5♠, 7♠} → {5♠, 2♦, 3♣, 5♥, 9♦, 8♣, 7♠}; el pivote 5♥ queda en su lugar definitivo.

Partición de Hoare [Hoare61, Hoare62]

1: pivot = A[low]
2: loop
3:     while A[low] < pivot do low++
4:     while A[high] > pivot do high−−
5:     if low < high then
6:         swap(A[low], A[high])
7:         low++
8:         high−−
9:     else
10:        return middle = high

Dos punteros que se acercan desde los extremos.

Invariantes: a la izquierda de low hay claves ≤ pivot; a la derecha de high hay claves ≥ pivot.

El pivote termina eventualmente en su lugar. Peor caso: n/2 swaps.

Quicksort de Hoare (recursión)

1: if low < high then
2:     middle = Partition(A, low, high)
3:     Quicksort(A, low, middle)
4:     Quicksort(A, middle + 1, high)

En el quicksort con Lomuto, la línea 3 usa middle − 1 (el pivote ya está en su sitio).

Propiedades: in-place pero NO estable. Usa O(log n) de espacio extra para la pila (recursiva o iterativa). Merge sort es mejor como ordenamiento estable.

Mejor caso: O(n log n)

Buen rendimiento ⇔ partición balanceada ⇔ buena elección de pivote.

Requiere un pivote perfecto siempre (mediana). Cada nivel cuesta cn y hay 1 + ⌈log n⌉ niveles. Es similar a Merge sort.

Peor caso: O(n²)

Requiere el peor pivote siempre: el menor o mayor elemento (p. ej. entrada ya ordenada con pivote en un extremo).

También ocurre cuando todos los elementos tienen la misma clave con la partición de Lomuto.

La recursión llega a profundidad O(n).

Caso promedio: O(n log n)

  • Pivote aleatorio: 50 % de probabilidad de partición buena (entre 1/4 y 3/4).
  • Partición promedio de 1/4 – 3/4 → niveles de log4/3 n.
  • Profundidad promedio de recursión: 2 log4/3 n.
  • Cada nivel tiene a lo sumo n elementos.

Mismo O(n log n) que merge sort, pero con constantes ocultas distintas.

🚀 Mejoras de Quicksort

Elementos iguales
Partición en tres vías (Problema de la bandera holandesa, Dijkstra 76): separa en < pivot, = pivot, > pivot. Compara A[i] con el pivote dos veces.
Mejor elección de pivote
Mediana de tres: aplicar insertion sort a {front, middle, tail} y elegir middle como pivote.
Pseudomediana de nueve [Ben93]: mediana de las medianas de tres grupos de tres.
Dual-pivot de tres vías [Yar09]: particiona en < p1, entre p1 y p2, > p2; funciona bien con claves repetidas.
Cambiar a insertion sort
Es más rápido en subarreglos pequeños. Usado en std::sort de GNU C++ y por Yaroslavskiy-Bentley-Bloch desde el sort de Java 7.

🧬 Introsort (introspective sorting) [Mus97]

Problema: una mala partición produce recursiones de profundidad O(n). Idea: limitar la profundidad de la recursión.

Introsort es un algoritmo híbrido: quicksort con estas mejoras:

  1. El pivote se elige con la mediana de tres.
  2. Si la profundidad de recursión supera 2⌊log₂ n⌋, cambia a Heap sort (siempre O(n log n)).
  3. Si el número de ítems es menor a un umbral (16), cambia a Insertion sort.

Cada implementación usa umbrales distintos: C++ (GCC: 16, LLVM: 30|6, .NET: ?), Java: 14, …

7 Cota inferior para ordenamientos por comparación

¿Se puede ordenar comparando elementos más rápido que n log n? No. Este es el argumento:

1

El número de permutaciones de n ítems es n! = n·(n−1)·(n−2)·…·3·2·1. El ordenamiento debe distinguir cuál de ellas es la entrada.

2

Un algoritmo que usa un árbol de decisión (cada nodo es una comparación a<b con respuesta T/F, que divide los casos posibles) tiene n! hojas. Como el árbol binario halla una hoja en ≥ log(n!) pasos, hace Ω(log(n!)) comparaciones.

Ej.: con 3 elementos (abc, acb, bac, bca, cab, cba) las comparaciones a<b, a<c, b<c separan las 6 permutaciones hasta llegar a una hoja.

3

log(n!) ∈ Θ(n log n):

  • Cota superior: n! ≤ nⁿ ⇒ log(n!) ≤ n·log n ⇒ log(n!) ∈ O(n log n).
  • Cota inferior: n! ≥ n·(n−1)·…·⌈(n+1)/2⌉ ≥ ⌈n/2⌉^⌈n/2⌉ (hay ⌈n/2⌉ factores, todos ≥ n/2) ⇒ n! ≥ (n/2)^(n/2) ⇒ log(n!) ≥ (n/2)·log(n/2) ⇒ log(n!) ∈ Ω(n log n).

✅ Consecuencia

Todo algoritmo de ordenamiento por comparación realiza Ω(n log n) comparaciones. Introsort, Quicksort, Merge sort y Heap sort son eficientes (alcanzan esa cota; quicksort en el caso promedio).

🧠 Regla rápida para elegir

  • Necesito estabilidad → Merge sort (o Insertion sort si es pequeño / casi ordenado).
  • Poca memoria extra y garantía O(n log n) → Heap sort.
  • Rapidez general en la práctica → Quicksort (o mejor, Introsort, que evita el peor caso).
  • Entrada pequeña o casi ordenada → Insertion sort.
